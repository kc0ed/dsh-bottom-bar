# 价格模型重构设计(会话整理 · 2026-08-17)

> 本文档记录与用户多轮讨论的原始需求、已拍板决策、待确认问题。
> 背景:设置页"模板卡/价格表"被用户多次吐槽(折叠跳页、拥挤、表达不了复杂价格结构),
> 核心诉求是把「价格定义」升级为完整的多维模型,并用 tab 式 UI 替代折叠式。

---

## 一、需求要义(用户原话整理)

1. **现在价格表很难受**:调价格要"点来点去";折叠(展开/收起)会**撑高整个页面**、要滚鼠标,来回调整很费劲。
2. **偏好 tab 式左右切换**(像浏览器标签页):整体结构可控,切换只变那一小块,页面不跳。
3. **价格定义是多维的**,不只是"模型 id + 一个价":
   - 主体:厂商(提供商)级 vs 中转(聚合商)级——中转有自己的峰谷,也可能"参考别家"
   - 峰谷:高峰价 / 低谷价(已有,要保留并通用化)
   - **上下文长度分段**:超过临界上下文长度(如 272K/256K/500K)后换另一套价;有的渠道"超档直接 ×2 原价"
   - 币种:CNY(中国区)/ USD(国际)两套官方价并存(已有)
4. **编辑哲学 = 比例优先**:
   - 用户只填**输入价** → 系统**自动匹配厂商**(检测到 gpt → 自动标 OpenAI,deepseek → DeepSeek…)→ 按厂商官方比例自动派生**缓存读/缓存写/输出** → 用户只需**确认**
   - 有比例后"只要填输入价 + 确定厂商匹配就够了",非常舒服
   - 比例预览区:按当前输入价 + 当前比例,展示输入/缓存读/缓存写/输出的推算结果
5. **确认交互**:厂商旁一个确认位置;待确认状态用**沿卡片边缘流动的光**(类似贪吃蛇沿边缘行进)+ 官方背景色表示"等待确认";配确认/取消按钮
6. **预设价格来源**:官方价格可从渠道侧获取(opencode 有价格表;内置厂商模板已有,未来可引入更多数据源)
7. **长度分段临界点**:各模型各自填(官方就是各模型不同:272K/256K/500K 不等)

## 二、已拍板决策(D 系列)

| # | 决策 | 说明 |
|---|---|---|
| D1 | **UI 用 tab,不用折叠** | 三个 tab:价格表 / 新增价格 / 厂商;tab 切换只变内容区,页面不跳高 |
| D2 | **价格表 tab 内分两部分** | ①已设定好的价格;②未设定但已有 token 消耗记录的模型(现"用过的模型·未配置价格"区,挪进 tab 对齐) |
| D3 | **长度分段临界点随模型** | 每个模型自己填临界上下文长度(≤X 一档 / >X 另一档),默认空=不分段;内置模型可预置官方档位 |
| D4 | **超档价格也有比例** | 建议提供常用倍率(如 ×2)作自动建议,用户自行确认是否匹配(有的渠道就是超档直接乘 2) |
| D5 | **新增流程 = 填输入价 → 自动匹配厂商 → 比例派生 → 确认** | 确认前有"待确认"状态指示(边缘流光 + 官方背景色),确认/取消按钮收尾;比例预览区实时展示四桶推算 |
| D6 | **厂商数据源** | 内置厂商官方模板(已有)+ 可引入渠道侧价格表(opencode 等)作预设源 |
| D7 | 峰谷/渠道白名单/币种偏好等 | 位置待定(见 Q-D) |

## 三、待确认问题(Q 系列,附推荐)

### Q-A:临界点与档位的内置预置策略
- 官方内置模型(deepseek-v4 / gpt-5.x / qwen3.x 等)是否内置各自的官方临界点(272K/256K…)?
- **推荐**:内置预置官方档(改价格时自动带出,可改),自定义模型默认不分段

### Q-B:超档比例的默认行为
- 超档价默认 = 原价 ×2?还是每模型不同?
- **推荐**:建议值 ×2(最常见),用户可改;比例预览区照常展示超档四桶推算

### Q-C:中转(聚合商)"参考别家"怎么做
- 厂商 tab 里,中转商比例 = 手动自定义,还是"选择参考某厂商官方比例 + 自定义覆盖"?
- **推荐**:提供"参考厂商"下拉(选 OpenAI/DeepSeek/…)+ 可微调,同时支持纯手动

### Q-D:峰谷时段/渠道白名单/币种偏好放哪
- 选项:①设置页主区(现状);②价格表 tab 顶部;③新增价格 tab
- **推荐**:保持设置页主区(峰谷开关/时区/渠道白名单是全局行为,和"定价结构"分开)

### Q-E:确认光效的具体形态
- "贪吃蛇沿边缘流动的光"——圆角卡片边缘一圈走马灯光带,品牌色,2s 一圈?
- **推荐**:边缘渐变光带沿边框循环流动(品牌色→透明),仅待确认时显示;确认后停止并变常驻"已确认"状态

### Q-F:长度分段"精确调算"的取档规则
- 按请求实际输入上下文量选档:`实际量 ≤ 临界` → 低档价;`> 临界` → 高档价
- 叠加峰谷:高档 × 峰谷各自独立(每档可有自己的 peak)
- **推荐**:确认此取档规则;峰谷作用于当前选中的档位之上
